# Випадкові глітчі

Під час гри автоматично виникають короткі хвилі навмисного візуального й
звукового хаосу. Перша — через 12–30 секунд активної гри; кожна триває
4–9 секунд, наступна приходить після випадкової паузи 18–55 секунд.

- Рожево-чорна шахівниця вкриває випадкові ділянки предметів, будівель,
  машин та інтер'єрів. Вибір ділянок змінюється під час хвилі.
- Смуги геометрії смикаються вбік; частина персонажів стає чорними силуетами.
- Двигуни, кроки й сирени заїкаються, дробляться, обриваються та змішуються
  з цифровим писком. Ефект проходить через наявний стереообмежувач піків.
- Меню призупиняє таймер і вимикає ефекти. Після хвилі картинка й звук
  повертаються до звичайного стану.

Ефекти суто косметичні: колізії, позиції, здоров'я, економіка та збереження
не змінюються. Геометрія світу залишається в кешованих VBO; нових текстур,
залежностей і покадрового завантаження мешів немає. Звукова історія має
фіксований розмір. Під час хвилі тимчасово використовується вбудований
шейдер; після неї повертається вибраний shader pack.

Це окремий Cargo workspace у `UGLGLITH/`. Запуск: `./run.sh` у цій папці
або `cd UGLGLITH && cargo run --release`. Потрібні Rust, SDL2 та OpenGL.
Основна гра й попередні ZIP/APK не змінюються.

Для відтворюваної перевірки можна негайно запустити хвилю в smoke-режимі:

```sh
JBRS_GLITCH=1 JBRS_SCENE=prison JBRS_CAPTURE=/tmp/glitch.ppm cargo run --release -- --smoke-test
```

`JBRS_GLITCH` діє лише з `--smoke-test`. Звичайна гра завжди використовує
випадковий таймер. GLES2 перевіряється окремою збіркою `--features gles`.

## Перевірка

- `cargo fmt --all -- --check`.
- `cargo clippy --workspace --all-targets` — без попереджень.
- `cargo test --workspace` — усі тести пройдено; окремо перевірені таймер,
  пауза в меню, відновлення звуку, межі піків і незалежність від розміру блока.
- Release-збірки desktop та `--features gles`; Windows GNU — `cargo check`.
- По 90 кадрів примусової хвилі на Mesa llvmpipe з контекстами OpenGL 2.1
  та OpenGL ES 2.0, включно зі знімками екрана. SDL audio — dummy device.

Ironlake, реальний телефон, фізичні динаміки та Windows runtime тут не
тестувалися. Вимірювання програмного рендерера не є оцінкою цільового FPS.
